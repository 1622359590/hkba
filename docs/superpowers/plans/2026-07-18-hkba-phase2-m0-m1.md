- **D1 架构延续**：保留 Next.js 16 + React 19 + Express 4 + SQLite（better-sqlite3）与宝塔单域名代理部署，渐进升级，不重写框架、数据库或部署链路。（主设计 §1、§13；验收 §15）
- **D2 模型分层**：页面身份与页面版本分离（Page / PageVersion / PageBlock），草稿与正式版本并存，正式站点只读已发布版本。（数据规范 §2.1–2.3）
- **D3 ID 策略**：新表统一使用文本 UUID 主键；现有旧表保留整数 ID；通过映射表桥接新旧 ID。（数据规范 §2.1；组件目录 §1 通用字段）
- **D4 迁移纪律**：数据库变更采用版本化 migration 机制；破坏性 schema 变更遵循"扩展—迁移—收缩"，不在一次部署中直接删除旧字段。（验收 §10、§15）
- **D5 旧字段保留**：`pages.content_*` 与 `news.content_*` 保留至旧数据迁移验证与回滚窗口结束。（验收 §15）
- **D6 组件注册表**：组件定义以代码注册表为准，数据库只保存可搜索的同步元数据，不允许后台创建任意组件代码。（数据规范 §2.7）
- **D7 新闻单一实体**：新闻只维护一份；页面组件保存查询条件不复制正文；年份规则 `displayYear ?? year(publishedAt)`。（数据规范 §1、§6）
- **D8 媒体引用**：组件以稳定 ID 引用 `MediaAsset`，`MediaReference` 记录引用关系，不把临时上传 URL 当作内容数据。（数据规范 §2.6）
- **D9 双语同版本**：中英文组件属于同一页面版本、一次发布同时切换；缺失翻译作为发布检查项，不创建互相漂移的双版本。（数据规范 §2.2）
- **D10 存储路线**：首期继续使用 SQLite + 本地上传；PostgreSQL 与对象存储迁移在接口边界稳定后单独规划，不与页面构建器首期上线绑定。（主设计 §13；验收 §15）

**Goal:** M0 建立可安全演进的工程基线（实施计划、只读数据盘点、版本化 migration 机制、性能基线方法），M1 在此基线上以增量 migration 新增页面构建后台所需的全部新表。

**Architecture:** 现有 `backend/db/schema.sql` 收编为 `backend/db/migrations/001_baseline.sql`；`backend/db/migrate.js` 维护 `schema_migrations` 表并按序应用迁移；`backend/db/init.js` 改为调用 migrator。老库检测到 `admins` 表已存在且 `schema_migrations` 为空时，将基线标记为已应用而不重跑；新库从头执行。M1 新表一律使用文本 UUID 主键，旧表整数 ID 经 `legacy_id_map` 桥接（D3）。

**Tech Stack:** Node.js 24、Express 4、better-sqlite3 11、node:test（Node 内置测试器）、Next.js 16、React 19、Tailwind CSS 4

## M2：会话、角色与审计（本变更实施，2026-07-18 完成）

依据主设计 §12、数据规范 §2.8/§13。已批准决策 D3（过渡）：Bearer→Cookie **双模式并行**，前端 UI 全部切完后才移除 Bearer（移除不在本里程碑）。

### 机制设计要点

- **双模式判定顺序**：`middleware/auth.js` 优先校验 HttpOnly 会话 Cookie（`hkba_admin`），无效或缺失时回退 `Authorization: Bearer`；**无效 Cookie 不阻断有效 Bearer 回退**；两者皆无 → 401。`req.authMethod` 记录实际模式。
- **Cookie 属性**：HttpOnly + SameSite=Lax + `Secure`（仅 `NODE_ENV=production`，本地 http 不设否则浏览器拒存）+ `Max-Age=604800`，与现有 7 天 JWT 一致；手写序列化/解析（`lib/cookies.js`），零新增依赖。
- **CSRF 方案**：Cookie 会话的写请求（非 GET/HEAD/OPTIONS）必须携带自定义头 `x-requested-with: XMLHttpRequest`，缺失 → 403。选它的理由：SameSite=Lax 已挡住跨站 POST Cookie 作为基层，自定义头提供跨站表单无法伪造的显式证明，比双提交 token 简单且无状态（不用存/发 token）；Bearer 请求天然免疫 CSRF，豁免检查。
- **登出**：`POST /api/auth/logout` 始终清 Cookie（Max-Age=0），能识别身份时写审计；过期会话也能正常登出。
- **RBAC**：`lib/rbac.js` 种子 3 角色（super_admin/editor/publisher）× 6 权限点（content.read/content.write/publish/rollback/media.delete/system.admin），全部 `INSERT OR IGNORE` 幂等，随 `initDatabase()` 执行；旧 `admins` 整数 ID 经 `user_roles` 桥接；**首个 admin 自动挂 super_admin**（防自锁）。`middleware/requirePermission(code)` 查询失败闭门（403）。挂载点仅两处验证机制：改密（`content.read`）、上传（`content.write`）；全量铺开随各模块 API。
- **审计**：`lib/audit.js` 写 `audit_events`（actor、action、object、detail JSON、ip、session、user_agent）；接入登录成功/失败、登出、改密；**写库失败只 console.error，绝不让主流程 500**（测试覆盖 DROP TABLE 后登录仍 200）。
- **前端**：`adminApi.ts` 一律 `credentials:'include'` + CSRF 头，localStorage Bearer 作回退（过渡期）；layout 改 `/api/auth/verify` 探测会话（替代 localStorage 检查）；登录页支持 `?next=` 回跳（仅接受 `/admin` 内部路径防开放重定向）；401 时先派发 `hkba:session-expired` 事件再跳登录——`lib/sessionGuard.ts` 让表单页快照/恢复未保存编辑（30 分钟有效），已在新闻页接线作范式。

### 偏差说明

1. CSRF 采用自定义头方案而非双提交 token（理由见上）。
2. `audit_events.user_agent` 经 `008_audit_events_user_agent.sql`（ALTER ADD COLUMN）补充；SQLite 无 `ADD COLUMN IF NOT EXISTS`，单次应用由 `schema_migrations` 保证，区别于纯幂等迁移文件。
3. `requirePermission` 只挂改密与上传两个端点验证机制，其余端点随各模块 API 里程碑铺开。
4. 前端保留 localStorage Bearer 回退；`Set-Cookie` 用手写序列化而非 `res.cookie`（零依赖且可纯函数测试）。
5. 会话过期表单保留机制先在新闻页接线，其余表单随页面构建器 UI 里程碑推广。
6. 部署自测脚本 `test-seed-first-deploy.sh` 增补复制 `lib/rbac.js`（init.js 新依赖；生产 rsync 全仓不受影响）。

## M3：组件注册表 + 页面树/草稿/区块 API（本变更实施，2026-07-18 完成）

依据主设计 §5/§8/§10、目录规范 §1-§8、数据规范 §2.7。交付两部分：后端组件注册表（契约唯一事实源）与页面树/草稿/区块管理 API。

### 组件注册表（`backend/components/registry/`）

- **30 个组件定义**（catalog §1-§8）：newsDisplay 6（news.grid/list/featured/archive/category-tabs/related）、newsBlocks 8（news.header/media.image/media.gallery/media.video/content.rich-text/content.quote/content.embed/association.related-pages）、content 5、association 6、layout 5（含 section/columns/grid 等布局容器）。
- **手写 schema 校验器**（`components/validate.js`）而非 zod：零新增依赖（对齐 Global Constraints），字段类型/必填/枚举/范围/长度/数组项 + 未知字段拒绝（data-api §5），纯函数可单测。
- **注册表 API**：`getDefinition` 扫数组（支持运行时注入测试定义）、`validateBlockConfig`（错误带 `contentZh./contentEn./settings.` 前缀）、`migrateConfig` 链式纯函数、`listDefinitions` 去函数化输出元数据、`allowsPageType` 页面类型约束。
- 共享 `yearMode` 查询设置 + `specificYearRule`（yearMode=specific 时 year 必填）用于全部 6 个新闻展示组件。

### 页面/草稿/区块 API（`routes/admin/pages.js` + `routes/admin/components.js`）

统一响应格式 `{success, data|error{code,message,fields}, meta.requestId}`（`lib/respond.js` 的 requestContext 中间件生成 requestId；错误码 VALIDATION_FAILED/NOT_FOUND/FORBIDDEN/REVISION_CONFLICT 409/REFERENCE_EXISTS 409/INTERNAL_ERROR）。全部写端点挂双模式鉴权 + `requirePermission` + 审计。

- `GET /api/admin/components/definitions`：注册表元数据（content.read）。
- 页面树：`GET /api/admin/pages/tree`（嵌套 + 状态标记）、`POST /api/admin/pages`、`PATCH /api/admin/pages/:id`（标题/导航状态/改 slug）、`POST /api/admin/pages/:id/move`（重算子树 path，禁止移入自身后代）、`POST /api/admin/pages/:id/duplicate`（连同草稿区块复制）、`DELETE /api/admin/pages/:id`（回收站，`childrenStrategy=refuse|trash|move`）、`POST /api/admin/pages/:id/restore`。
- 草稿：`GET /api/admin/pages/:id/draft`（首次访问从 published 复制或建空草稿，`lib/drafts.js` getOrCreateDraft）、`PATCH .../draft`（标题等元数据）。
- 区块：`POST/PATCH/DELETE /api/admin/pages/:id/draft/blocks[/:blockId]`、`POST .../blocks/reorder`（全排列校验）、`POST .../blocks/:blockId/duplicate`。全部经 `applyDraftMutation`：`expectedRevision` 乐观锁（不符 → 409 REVISION_CONFLICT 带 currentRevision）+ `mutationId` 幂等重放（`009_mutation_log.sql`，命中直接返回已存响应）。
- 树规则：最多 3 级、slug 同级唯一跨级可复用、布局嵌套仅 2 层且仅 layout 可作父、删除有子区块的块 → 409 REFERENCE_EXISTS。

### 偏差说明

1. 实际路径带 `/api` 前缀（`/api/admin/pages/tree` ↔ spec `/admin/pages/tree`），与既有路由一致。
2. **草稿校验宽容**：区块保存时 `contentEn` 的 required 错误被过滤（`validateBlockConfig` 的 `allowMissingEn` 选项）——spec §10 允许中文先存草稿，英文完整性是发布检查项（M6）而非保存检查项。
3. `news.related` 的 `allowedPageTypes` 为 `['news']`（仅新闻详情模板），newsDisplay helper 因此支持参数覆盖；媒体类区块（media.image 等）按目录规范页面/新闻共享 `['news','page']`。
4. slug 改名：未发布节点直接改；已发布节点写 `redirects` 表（upsert from_path → 301）。预览/发布端点留 M6。
5. duplicate 区块时 anchor 置 NULL，避免撞 `(version_id, anchor)` 唯一索引。
6. `DELETE` 的 `expectedRevision` 经 query 传递（body 亦可），兼容不发 body 的客户端。
7. publisher 角色 403 走 `requirePermission` 既有响应形状；新统一错误格式仅用于 M3 新端点。

## M4：媒体上传管线与媒体库 API（本变更实施，2026-07-18 完成）

依据数据规范 §2.6/§7、决策 D8（稳定 ID 引用）与 D10（首期本地存储）。交付：媒体资产存储校验管线、引用提取同步、媒体库管理 API。

### 实施要点

- **存储管线**（`lib/mediaStore.js`）：魔数嗅探判定类型（不信客户端 MIME）；允许 JPEG/PNG/WebP/AVIF/SVG/PDF，图片 ≤15MB、PDF ≤30MB；SVG 存储前清理（script/foreignObject 元素、on* 事件属性、javascript: URL）；sha256 校验和；`storage_key = media/<uuid>.<ext>` 写入 uploads 根（`HKBA_UPLOADS_DIR` 可覆盖，测试用临时目录）。

### 偏差说明

1. D10 本地存储 → 单段 multipart `POST /uploads` 合并 spec §7 的签名直传三步（uploads → 对象存储 → complete）；`variants` 保持 `[]`，响应式变体生成留给后续图像处理里程碑（引入 sharp 等原生依赖需单独评估，零依赖约束优先）。

3. GIF/ICO 不在 spec §7 允许列表，新管线不支持；旧 `/api/upload`、`/api/media` 路由保持不动兼容旧后台（渐进升级）。
4. 无新 migration：media_assets/media_references 表由 005 提供；无新 npm 依赖（multer 既有）。

## M5：新闻实体 API 与新闻查询（本变更实施，2026-07-18 完成）

依据数据规范 §2.4-2.5/§6、组件目录 §3、决策 D7（新闻单一实体）。交付：新闻草稿/修订/正文区块管理 API、栏目与标签管理、公开查询库（年份回退语义锁定）。预览/发布/撤回属 M6；公开查询端点的对外挂载属前台切换里程碑。

### 实施要点

- **新闻草稿协议**（`lib/newsDrafts.js`）：与页面草稿同构——每篇一条 `news_revisions` draft 行，`expectedRevision` 乐观锁（409 REVISION_CONFLICT 带当前修订）+ `mutationId` 幂等重放；区块随修订号重写（`news_blocks(news_id, revision)`，006 schema 约束"区块与元数据同修订发布"）。
- **API**（`routes/admin/news.js`）：`GET /api/admin/news`（status/categoryId/year/lang=missing-en/q 筛选 + 分页，默认排除回收站）、`POST /`（建 draft：revision 1 + 自动 `news.header` 区块 + 栏目/标签映射 + 封面引用）、`GET /:id`（news + draft snapshot + blocks + 完整度标记）、`PATCH /:id`（元数据 + 可选全量 blocks 替换；区块经注册表校验 + `validateNewsBlocks` 标题区规则）、`POST /:id/restore-revision`（从历史修订复制 snapshot+blocks 生成新草稿）、`DELETE /:id` + `POST /:id/restore`（回收站）。
- **栏目/标签**（`routes/admin/newsTaxonomy.js`，一个工厂两个路由器）：`/api/admin/news-categories`、`/api/admin/news-tags` 的 GET/POST/PATCH/DELETE；栏目支持 parent_id（自父/循环拒绝）；被新闻映射或有子级时删除 → 409 REFERENCE_EXISTS；列表带 news_count。
- **媒体引用扩展**：封面 → `news_cover(news_id)`；正文区块媒体字段 → `news_block(block_id)`，随 blocks 重写在事务内同步；永久删除保护对新闻引用同样生效。
- **公开查询库**（`lib/newsQuery.js`）：`EFFECTIVE_YEAR_SQL = COALESCE(display_year, year(published_at))` 单 SQL 实现 D7 年份回退；`queryPublishedNews`（仅 published + year/category/tag + 分页）、`getPublishedNewsBySlug`（published_revision 区块）、`listPublishedYears`（仅真实已发布内容）。
- **migration 010**：`mutation_log.page_id` RENAME → `owner_id`（同一幂等协议服务新闻草稿；009 未上生产，重命名是诚实形状；SQLite 自动改写依赖索引）。

### 偏差说明

1. PATCH 的 blocks 为**全量替换**语义（客户端发送完整有序列表，服务器按数组序写 sort_order）——spec §6 只有单 PATCH 端点（区别于页面区块的细粒度端点），新闻正文短、无嵌套，全量替换更简单且天然配合修订重写。
2. 未提供 blocks 时旧区块按原 ID 重键到新修订号（内容不变，引用同步保持）。
3. 公开端点（`GET /api/news?year=…`、`/api/news/:slug`、`/api/news/years`）此里程碑只落查询库并测试锁定语义——`/api/news` 路径仍由旧路由服务线上站点，挂载切换属最终迁移里程碑。
4. preview/publish/withdraw/restore 发布生命周期属 M6；M5 的 `POST /:id/restore` 仅回收站恢复。
5. 回收站恢复统一回到 `draft` 状态（不记忆回收前状态；发布状态由 M6 发布流重建）。

## M6：预览令牌与发布引擎（本变更实施，2026-07-18 完成）

依据数据规范 §8-§12。交付：发布检查、预览令牌、页面/新闻发布事务、撤回、页面回退、发布日志与保留剪枝。

### 实施要点

- **发布检查**（`lib/publishChecks.js`）：结构化问题数组 `{objectId, blockId, lang, field, code, hint}`。页面：路径唯一、层级 ≤3 且父链未删、组件类型/版本受支持、区块树规则、**完整双语校验**（草稿宽容结束于发布——contentEn 必填项此时强制）、媒体存在且 active、内部链接可解析（已发布路径或 redirects）、page 节点 SEO 标题/描述/分享图完整。新闻：中英标题/摘要、栏目 ≥1、displayYear 四位、slug 唯一、封面/正文媒体、header 规则 + 完整双语校验。
- **预览令牌**（`lib/previewTokens.js`）：绑定对象 + 修订 + 创建人 + 过期（默认 30 分钟），库中只存 sha256；`GET /api/preview/:token`（公开）返回绑定修订内容，`X-Robots-Tag: noindex` + `Cache-Control: no-store`；草稿已推进 → 410 PREVIEW_STALE；无效/过期 → 404。
- **发布事务**：页面（`POST /api/admin/pages/:id/publish`，publish 权限）——expectedRevision 复核 → 检查（422 PUBLISH_CHECK_FAILED 带问题数组）→ 事务内旧版本 superseded、草稿版本 published、节点指针切换、写 `publish_records`、保留剪枝（`lib/publish.js`，每页留最新 20 个已发布/被取代版本，连带清理区块与媒体引用）。新闻同理（published_revision 切换 + published_at，**草稿以修订号+1 的复制继续**）。撤回（页面清 published_version_id、新闻置 withdrawn）与页面回退（`POST /:id/rollback`，rollback 权限，历史已发布版本复制为 max+1 新草稿）均写 publish_records 与审计。
- **修订号语义修正**：`getOrCreateDraft` 发布后重建草稿改为 `max(revision)+1`（此前复用已发布修订号会撞 `UNIQUE(page_id, revision)`；§11 修訂號繼續遞增），并从源版本复制 seo。
- **UTC 解析修正**：`previewTokens`/`retention`/`newsYear` 解析 SQLite naive datetime 时补 `Z`（无时区标记才补）——此前按本地时区解析，非 UTC 机器上预览令牌立即"过期"、年份回退可能跨年漂移。

### 偏差说明

1. §10 第 7 步缓存刷新：项目尚无查询缓存层，post-commit 钩子在代码中标注，随前台渲染里程碑落地；不存在"刷新失败"面。
2. 页面撤回保留版本行状态为 published 仅清节点指针（历史可回退）；新闻撤回置 withdrawn 保留 published_revision。
3. 新闻发布日期取发布时刻（`datetime('now')`），不强制编辑手填——spec"发布日期完整"由系统保证。
4. 预览端点返回结构化 JSON 内容而非渲染 HTML——渲染属前台切换里程碑；noindex/no-store 语义已具备。

### 偏差说明

1. redirects 构建时生效：运行期新增行需重新部署（变化极少，且配合 M9 迁移一次性写入，可接受）。
2. BlockRenderer 不按组件类型拆分动态 import：单模块体积已小，拆分 30 个 lazy 边界得不偿失；性能预算以"公开树无 admin 依赖"为硬性指标并已验证。
3. news.archive / news.category-tabs / news.related 与 association.* 组件在公开上下文仍为占位卡：其真实查询渲染随 M9 迁移后的组件专项落地；news.grid/list/featured 已真实渲染。

5. 默认站点源为 `https://www.hkba.hk` 占位：生产必须以 `NEXT_PUBLIC_SITE_URL` 注入真实域名，否则 canonical/OG/sitemap 绝对 URL 不正确。
