**已批准决策（D1–D10，2026-07-18 全部批准）：**

- **D1 架构延续**：保留 Next.js 16 + React 19 + Express 4 + SQLite（better-sqlite3）与宝塔单域名代理部署，渐进升级，不重写框架、数据库或部署链路。（主设计 §1、§13；验收 §15）
- **D2 模型分层**：页面身份与页面版本分离（Page / PageVersion / PageBlock），草稿与正式版本并存，正式站点只读已发布版本。（数据规范 §2.1–2.3）
- **D3 ID 策略**：新表统一使用文本 UUID 主键；现有旧表保留整数 ID；通过映射表桥接新旧 ID。（数据规范 §2.1；组件目录 §1 通用字段）
- **D4 迁移纪律**：数据库变更采用版本化 migration 机制；破坏性 schema 变更遵循"扩展—迁移—收缩"，不在一次部署中直接删除旧字段。（验收 §10、§15）
- **D5 旧字段保留**：`pages.content_*` 与 `news.content_*` 保留至旧数据迁移验证与回滚窗口结束。（验收 §15）
- **D6 组件注册表**：组件定义以代码注册表为准，数据库只保存可搜索的同步元数据，不允许后台创建任意组件代码。（数据规范 §2.7）
- **D7 新闻单一实体**：新闻只维护一份；页面组件保存查询条件不复制正文；年份规则 `displayYear ?? year(publishedAt)`。（数据规范 §1、§6）
- **D8 媒体引用**：组件以稳定 ID 引用 `MediaAsset`，`MediaReference` 记录引用关系，不把临时上传 URL 当作内容数据。（数据规范 §2.6）
- **D9 双语同版本**：中英文组件属于同一页面版本、一次发布同时切换；缺失翻译作为发布检查项，不创建互相漂移的双版本。（数据规范 §2.2）
- **D10 存储路线**：首期继续使用 SQLite + 本地上传；PostgreSQL 与对象存储迁移在接口边界稳定后单独规划，不与页面构建器首期上线绑定。（主设计 §13；验收 §15）

**Goal:** M0 建立可安全演进的工程基线（实施计划、只读数据盘点、版本化 migration 机制、性能基线方法），M1 在此基线上以增量 migration 新增页面构建后台所需的全部新表。

**Architecture:** 现有 `backend/db/schema.sql` 收编为 `backend/db/migrations/001_baseline.sql`；`backend/db/migrate.js` 维护 `schema_migrations` 表并按序应用迁移；`backend/db/init.js` 改为调用 migrator。老库检测到 `admins` 表已存在且 `schema_migrations` 为空时，将基线标记为已应用而不重跑；新库从头执行。M1 新表一律使用文本 UUID 主键，旧表整数 ID 经 `legacy_id_map` 桥接（D3）。

**Tech Stack:** Node.js 24、Express 4、better-sqlite3 11、node:test（Node 内置测试器）、Next.js 16、React 19、Tailwind CSS 4

## 回滚策略

- **代码**：本变更在 `phase2/m0-m1-data-layer` 分支，未 push；回滚即还原分支提交，不触发生产。
- **数据库**：`001_baseline.sql` 为纯扩展且幂等；老库只新增 `schema_migrations` 表与一行记录，不改动任何既有表与数据。回滚代码后遗留的 `schema_migrations` 表无害（"扩展"阶段产物），后续迁移可继续在其上前进。
- **服务器执行迁移前**：先 `cp backend/db/hkba.db backend/db/hkba.db.bak-<date>` 快照，再用 `node backend/scripts/inventory.js --db <快照>` 核对盘点。
- **内容回滚与代码回滚分离**：内容版本回退属于后续发布服务能力，不依赖本次机制回滚（验收 §10）。

## 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 本地 Node 24 下 `better-sqlite3@11` 无预编译二进制，node-gyp 若取到含空格路径的 Python 会编译失败 | 环境级修复：以无空格路径 Python 安装（`npm_config_python=/usr/bin/python3 npm install`）；不升级依赖、不改 lock，生产 `npm ci` 行为不变 |
| 生产老库首次运行新 `init.js` 触发基线检测误判 | 检测条件保守（`schema_migrations` 为空 **且** `admins` 存在）；基线 SQL 全量 `IF NOT EXISTS`，即使执行也不改数据；上线前先在生产快照上演练 |
| `schema.sql` 删除后有残留引用 | 已全仓 grep：仅 `init.js` 与首部署脚本引用，均已更新 |
| 盘点脚本对在线 WAL 库只读打开 | better-sqlite3 `readonly + fileMustExist` 不加写锁；脚本无写路径 |
| 迁移文件被改名导致历史记录错乱 | 迁移名一旦合入即冻结；新变更只能追加更高编号文件（计划约定） |
