# HKBA 验收、迁移与运维规范

日期：2026-07-15
关联主设计：[HKBA 轻量页面构建后台总设计](./2026-07-15-hkba-lightweight-page-builder-design.md)

## 1. 目的

本文定义设计何时算真正交付，并约束旧数据迁移、测试、部署、备份和恢复。当前仓库验证基线为：后端在 `backend/` 执行 `npm test`，前端在 `frontend/` 执行 `npm run build`。实施计划应在每个阶段补充与改动范围直接对应的测试命令。

## 2. 第一阶段验收场景

### 2.1 登录和权限

- 有效管理员可以登录并进入星系控制中心。
- 无效登录不泄露用户名是否存在。
- 内容编辑不能发布、回退或管理用户。
- 发布人员可以检查、发布和回退，但不能提升权限。
- 会话过期时保留未保存的本地编辑内容，并引导重新登录。

### 2.2 星系控制中心

- 初始只显示 HKBA 和网站、内容、媒体、系统一级节点。
- 节点能展示草稿、待发布、英文缺失和失败状态。
- 搜索可以定位页面、栏目和新闻模块。
- 键盘可在节点之间移动并打开模块。
- 减少动态效果设置开启后，持续动画停止或显著减少。

### 2.3 栏目与页面

- 可新增、复制、改名、隐藏和移动栏目及页面。
- 服务端拒绝循环层级和超过三级的层级。
- 删除有子项栏目时必须选择子项处理方式。
- 页面路径全站唯一；修改已发布路径时生成重定向。
- 页面树准确显示草稿、发布和翻译状态。

### 2.4 页面工作室

- 左右抽屉默认不永久挤压中央画布。
- 专注模式可以隐藏所有面板并恢复。
- 组件可以添加、复制、排序、隐藏和删除。
- 无效嵌套被阻止并显示原因。
- 中文和英文可以分别编辑并显示完整度。
- 桌面、平板和手机预览使用相同组件配置。

### 2.5 新闻

- 新闻正文可以组合标题、富文本、图片、图集、引用和附件。
- 新闻元数据包含栏目、标签、发布日期和可选显示年份。
- 新闻展示组件可以按指定年份、最新年份、全部年份或访客选择年份查询。
- 同一新闻被多个页面引用时，修改和重新发布只维护一份新闻。
- 撤回新闻后，引用组件不再公开显示该新闻。

### 2.6 媒体

- 图片可以拖到组件和媒体库上传。
- 错误格式、超限文件和伪造 MIME 被拒绝并显示具体原因。
- 多文件上传中的单文件失败不影响其他文件。
- 媒体可以重复使用并查看引用位置。
- 正式版本仍在引用的媒体不能永久删除。
- 图片替代文字进入发布检查。

### 2.7 草稿和发布

- 自动保存生成递增修订号。
- 两个编辑会话不会静默覆盖彼此。
- 预览显示未发布草稿且不会被公共缓存或索引。
- 发布检查能定位具体页面、组件、语言和字段。
- 发布事务失败时正式站点保持旧版本。
- 回退以历史版本创建新草稿，而不是删除现有版本。

## 3. 测试层级

### 3.1 单元测试

- 所有组件 schema、默认值和迁移函数。
- 新闻年份计算和查询条件。
- 页面路径、层级、循环检测和排序。
- 权限判定和发布检查规则。
- 媒体类型、大小和引用规则。

### 3.2 集成测试

- 页面草稿保存、修订冲突、预览、发布和回退。
- 新闻正文组件与页面新闻展示组件之间的数据查询。
- 媒体上传完成、派生版本、引用和删除保护。
- 发布事务和缓存刷新任务。
- 回收站恢复和保留期清理。

### 3.3 端到端测试

至少覆盖：

1. 编辑人员登录，新增栏目和页面，添加 Hero 与新闻组件，上传图片并提交发布。
2. 发布人员检查英文缺失，补齐或明确覆盖，预览并发布。
3. 发布后前台页面显示指定年份的新闻。
4. 发布新版本后回退到上一版本。
5. 两个会话同时编辑同一页面并出现可恢复冲突。
6. 删除被正式页面引用的媒体被阻止。

### 3.4 视觉和可访问性测试

- 星系、页面工作室、新闻编辑器和媒体库关键状态截图。
- 组件在桌面、平板和手机的视觉回归。
- 键盘导航、焦点管理、对比度和减少动态效果检查。

## 4. 性能目标

- 后台主界面在正常办公网络下首个可交互时间目标小于 3 秒。
- 页面树 500 个节点时，搜索和展开响应目标小于 200ms。
- 星系初始只渲染一级节点；大型树按需展开。
- 页面画布 30 个常见组件时仍可顺畅选择和排序。
- 自动保存请求合并，持续输入不产生每字符写入。
- 前台页面继续遵守项目现有性能预算；页面构建器不能让未使用组件进入公开页面包。

正式实施计划开始时先测量当前首页、新闻页和后台页面基线；性能对比使用同一机器、同一数据集和相同构建模式，避免把开发模式与生产构建混为一谈。

## 5. 旧数据盘点

迁移前输出只读清单：

- 当前栏目、页面和路径。
- 新闻数量、年份、栏目、语言完整度和发布状态。
- Banner、成员、合作伙伴和站点设置。
- 图片 URL、文件类型、可访问性和重复文件。
- 当前用户及权限。
- 无法解析的富文本、失效链接和缺失媒体。

盘点结果不直接修改生产数据。

## 6. 迁移映射

历史模型建议映射：

| 历史内容 | 新系统 |
| --- | --- |
| Banner | 首页 `content.hero` 或轮播变体 |
| News | `News` + 标题区 + 富文本 `NewsBlock` |
| Member | 结构化成员数据 + `association.board/members` |
| Partner | 结构化伙伴数据 + `association.partners` |
| SiteConfig | 网站设置和全局联系信息 |
| 图片 URL | `MediaAsset` + 引用关系 |

每条迁移记录保存旧 ID、新 ID、来源、状态和错误原因，允许重复运行而不重复插入。

## 7. 迁移步骤

1. 在目标环境备份数据库和媒体。
2. 运行只读盘点并人工确认数量。
3. 建立新 schema 和组件定义。
4. 导入媒体，使用 checksum 去重，并记录失败文件。
5. 导入结构化数据和新闻。
6. 创建栏目树、页面草稿及组件实例。
7. 运行链接、媒体、双语和发布检查。
8. 在预览环境由内容负责人抽样和全量关键页检查。
9. 冻结旧后台短时间写入，增量同步最后变更。
10. 切换正式版本并保留回滚窗口。

## 8. 内容验收

- 记录迁移前后数量对比。
- 所有现有公开 URL 有新页面或重定向。
- 新闻发布日期、显示年份、栏目和正文顺序正确。
- 中英文不被互相覆盖；缺失翻译被标记而非自动伪造。
- 图片可以加载，关键图片具有替代文字。
- 理事、会员和合作伙伴顺序与业务确认一致。

## 9. 环境和配置

环境至少分为开发、预览和生产。敏感配置不进入仓库：

- 数据库连接。
- 会话和加密密钥。
- 对象存储凭证、桶和区域。
- CDN 或缓存刷新凭证。
- 预览 URL 和允许来源。
- 邮件或通知服务配置（启用后）。

预览环境使用独立数据库和媒体前缀，不能误写生产数据。

## 10. 部署与回滚

- 数据库迁移先在预览环境验证。
- 破坏性 schema 变更使用扩展—迁移—收缩流程，不在一次部署中直接删除旧字段。
- 应用部署支持回滚到上一可运行版本。
- 新代码必须兼容部署期间的前一个数据库状态。
- 发布内容版本与部署应用版本分开；回退内容不需要回滚代码。
- 部署完成运行健康检查、登录、页面读取、新闻查询和媒体访问冒烟测试。

## 11. 备份与恢复

- 当前 SQLite 数据库每日自动快照，生产上线初期至少保留 30 天；迁移 PostgreSQL 后切换为数据库级备份。
- 对象存储启用版本或删除保护，并设置合理生命周期。
- 每月至少验证一次备份可读取；每季度执行恢复演练。
- 恢复演练记录恢复点、耗时、失败和修正动作。
- 审计日志保留时间不短于内容版本和安全要求。

## 12. 监控

至少监控：

- 应用健康和错误率。
- 登录失败异常增长。
- 草稿保存、发布事务和缓存刷新失败。
- 媒体处理积压和上传失败率。
- 数据库连接、容量和慢查询。
- 对象存储容量和异常删除。

关键失败在后台显示可操作状态，并进入运维告警渠道。

## 13. 管理员手册

上线前提供简明中文手册：

- 登录和角色区别。
- 星系控制中心导航。
- 新增栏目和页面。
- 添加、排序和配置组件。
- 新闻正文、年份和展示组件。
- 图片上传、媒体复用和替代文字。
- 草稿、预览、发布和回退。
- 常见错误及恢复方式。

## 14. 上线门槛

必须全部满足：

- 第一阶段验收场景通过。
- 关键端到端和迁移验证通过。
- 数据库及媒体备份完成并可读取。
- 权限、会话、上传和富文本安全检查完成。
- 内容负责人确认栏目、首页、新闻、成员和合作伙伴。
- 正式域名、HTTPS、缓存和回滚方案验证。
- 没有未解释的高优先级错误或数据差异。

## 15. 当前仓库实施边界

`btcsam/hkba` 当前架构已经确认：

- 前端为 Next.js 16、React 19 和 Tailwind CSS 4。
- 后端为 Express、`better-sqlite3`、JWT 和 `multer`。
- 数据模型在 `backend/db/schema.sql`，现有数据库为 SQLite。
- 页面、新闻、媒体和上传 API 位于 `backend/routes/`。
- 后台页面位于 `frontend/src/app/admin/`，现有页面和新闻编辑器以固定表单及 HTML 文本为主。
- 生产访问通过 Next.js 同源代理转发 API 和上传文件，并已有宝塔自动部署文档。

因此首期实施必须：

- 复用现有鉴权、同源代理、后台基础控件和公开页面。
- 使用增量 SQLite migration 增加页面版本、组件和发布记录，不直接重建数据库。
- 保留旧 `pages.content_*` 与 `news.content_*` 字段直到迁移验证和回滚窗口结束。
- 在接口稳定后再单独规划 PostgreSQL、Prisma 或 OSS 迁移。
- 每次开始实施前同步 `origin/main`，重新确认已有部署修复没有改变代理或数据目录边界。
