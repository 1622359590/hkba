# 團隊身份結構管理設計

## 目標

把目前寫死在前端的團隊身份選項改造成可由後台管理的結構化數據。身份結構成為成員編輯、Studio 會員組件和公開頁面的唯一名稱與排序來源。

本設計取代 `2026-08-03-member-role-order-controls-design.md` 中依據導入數據推斷的六身份預設。正式預設以用戶確認的五種身份為準。

## 預設身份

| 代碼 | 繁體中文 | English | 順序 |
|---|---|---|---:|
| `honorary_chairman` | 榮譽主席 | Honorary Chairman | 10 |
| `chairman` | 會長 | Chairman | 20 |
| `vice_chairman` | 副會長 | Vice Chairman | 30 |
| `committee` | 委員 | Committee Member | 40 |
| `advisor` | 顧問 | Advisor | 50 |

## 數據模型

新增 `team_member_groups` 表：

- `code TEXT PRIMARY KEY`：穩定身份代碼，建立後不可修改。
- `label_zh TEXT NOT NULL`：繁體中文名稱。
- `label_en TEXT NOT NULL`：英文名稱。
- `sort_order INTEGER NOT NULL`：全局身份順序。
- `is_active INTEGER NOT NULL`：是否可再分配給成員。
- `is_legacy INTEGER NOT NULL DEFAULT 0`：是否由遷移補建的舊身份。
- `created_at`、`updated_at`：審計時間。

`team_members.group_name` 繼續保存身份代碼，避免重寫現有成員表和破壞既有接口。身份存在性由寫入 API 驗證；刪除身份前檢查引用數量。

## 遷移與兼容

遷移必須可重複執行：

1. 建立身份表。
2. 以 `INSERT OR IGNORE` 建立五個預設身份。
3. 掃描 `team_members` 中不同的 `group_name`。
4. 不屬於五個預設的舊代碼，補建為啟用的 legacy 身份；中英文名稱先使用原代碼，避免成員失聯，管理員之後可改名或轉移。

保留公開 `GET /api/team/groups` 返回身份代碼數組的舊格式。新增管理接口使用完整身份對象，避免破壞未知的舊客戶端。

## API

新增以下已認證接口：

- `GET /api/team/groups/all`：按 `sort_order` 返回全部身份、啟用狀態和成員數量。
- `POST /api/team/groups`：建立身份；驗證代碼格式、名稱和唯一性。
- `PUT /api/team/groups/:code`：修改中英文名稱與啟用狀態，不修改代碼。
- `PUT /api/team/groups/order`：接收完整代碼排列並原子更新順序。
- `DELETE /api/team/groups/:code`：僅在引用數量為 0 時刪除，否則返回 409。

成員新增與更新接口驗證 `group_name`：新分配只能使用存在且啟用的身份；編輯仍保留原本已停用的身份，直到管理員主動轉移。

## 後台界面

`/admin/team` 增加「成員管理」與「身份結構」兩個頁籤。

身份結構頁包含：

- 可拖動的身份行，並提供上下移動按鈕作為鍵盤替代操作。
- 中英文名稱、穩定代碼、啟用狀態和成員數量。
- 新增、編輯、停用和刪除操作。
- 已被引用的身份點擊刪除時，顯示「請先轉移 N 位成員」而不發送破壞性請求。
- 保存排序失敗時恢復原順序並顯示錯誤提示。

成員編輯窗口的身份選項改從管理接口載入。新增成員只看到啟用身份；編輯具有停用身份的成員時，該身份仍以「已停用」標記顯示。

## Studio 與前台排序

身份表的 `sort_order` 是全局預設順序。Studio 的會員名錄組件可以：

- 選擇要展示的身份。
- 使用全局身份順序，或保存組件自己的 `roleOrder` 覆蓋順序。
- 同一身份內按 `team_members.sort_order`，再按成員 `id` 穩定排序。
- 使用身份表的中英文名稱顯示身份標籤。

組件設置中引用已停用或已刪除身份時忽略該代碼，其他身份繼續渲染。若沒有選擇身份，默認展示全部啟用身份。

## 錯誤處理

- 身份代碼僅接受小寫字母、數字和下劃線，長度 2–40。
- 中英文名稱去除首尾空格且至少一項非空；缺少的另一語言回退到已填名稱。
- 不允許刪除仍被成員使用的身份。
- 不允許排序請求缺少或重複身份代碼。
- 至少保留一個啟用身份，避免新增成員無身份可選。
- 接口錯誤使用現有統一錯誤信封和狀態碼。

## 測試

- 遷移：新數據庫建立五個預設身份；重跑不重複；舊代碼安全補建。
- API：列表、建立、改名、停用、重排、刪除和 409 引用保護。
- 成員 API：拒絕未知或不可新分配的停用身份，允許保留原停用身份。
- 後台：身份載入、成員數量、拖動/按鈕排序、刪除提示和選項更新。
- 渲染：全局身份順序、組件覆蓋順序、身份篩選和同組穩定排序。

## 驗收標準

- 初次遷移後可看到五個預設身份。
- 管理員可在團隊管理內新增、改名、停用和排序身份。
- 已有成員的身份不能直接刪除。
- 成員編輯下拉框不再依賴硬編碼數組。
- Studio 與公開頁使用同一身份名稱和順序來源。
- 現有成員及未知舊身份不因升級而遺失。
