# 新建新闻自动生成 Slug 设计

## 目标

新建新闻时不再要求管理员手动填写 slug。系统自动提供合法且低碰撞的 slug，同时保留手动修改能力，并由后端保证所有创建入口都能获得唯一 slug。

## 已确认行为

- 点击后台新闻列表的“新建新闻”时，表单立即生成一次 slug。
- 默认格式为 `news-YYYYMMDD-xxxxxx`：日期使用本地日历日期，随机段使用六位小写字母和数字。
- 自动生成后不随中文标题、英文标题或其他字段变化，避免管理员编辑过程中 URL 意外改变。
- slug 输入框继续显示并允许手动修改。
- 新建按钮只要求中文标题；slug 为空时仍允许提交。
- 编辑已有新闻时沿用数据库中的 slug，不重新生成。

## 前端设计

- 将纯函数生成器放入独立的新闻 slug 工具模块，供表单和测试使用。
- 进入新建状态时创建全新的表单对象，并写入一次自动 slug；不得直接复用或修改共享的 `EMPTY_META` 对象。
- 表单提示改为“已自动生成，可修改；仅小写字母、数字和连字符”。
- 创建请求携带当前输入框中的 slug；如果管理员清空输入框，则省略 slug 或发送空值，由后端生成。

## 后端设计

- POST `/api/admin/news` 接受 slug 缺省或空字符串。
- 如果客户端提供非空 slug，继续执行现有格式与唯一性校验，不静默改写管理员输入。
- 如果未提供 slug，后端按同一格式生成候选值，并查询 `news_items`；发生碰撞时重新生成，直到获得唯一值。
- 后端生成后的最终 slug 用于数据库写入、审计记录和响应数据，确保所有后续流程读取同一个值。
- PATCH 现有新闻的 slug 行为保持不变：仅在明确提交 slug 时修改并校验。

## 随机性与边界

- 浏览器端与后端均使用 `crypto.randomUUID()`，移除连字符后截取前六位作为随机段，不使用 `Math.random`。
- 随机字符集限定为 `a-z0-9`，生成结果始终满足现有 `SLUG_PATTERN`。
- 后端唯一性循环设置有限重试次数；如果持续碰撞，返回统一的服务器错误，不写入部分数据。
- 日期只用于可辨识性和排序提示，不承担唯一性职责。

## 测试策略

- 前端纯函数测试覆盖格式、字符集、日期格式和连续生成结果不同。
- 后端测试覆盖缺省 slug 自动生成、显式 slug 保持不变、自动生成结果合法且已写入。
- 后端测试通过注入或替换候选生成器模拟首次碰撞，验证会重试并使用第二个唯一值。
- 运行前端相关测试、后端新闻路由测试与前端生产构建。

## 验收标准

1. 点击“新建新闻”后 slug 输入框已经有合法值，无需手动输入。
2. 管理员可以修改自动值，提交后保存修改后的 slug。
3. 清空 slug 仍可创建新闻，响应与数据库中包含后端生成的合法唯一 slug。
4. 自动 slug 符合 `^news-[0-9]{8}-[a-z0-9]{6}$`。
5. 新建按钮不再因 slug 为空而禁用，但中文标题为空时仍禁用。
6. 编辑已有新闻时 slug 不会自动变化。
7. 现有重复 slug、非法 slug 和 PATCH 校验行为不回归。
