# HKBA 生命周期运营仪表盘设计

## 目标

将现有的星系关系图替换为一个不重复左侧导航的运营驾驶舱。仪表盘根据网站所处阶段自动变化：新站提供设置引导，已运营网站只显示真实的未完成事项、最近发布和快速入口。

## 设计原则

1. 左侧导航负责进入模块，仪表盘负责告诉管理员下一步该做什么。
2. 不展示没有行动价值的统计数字。
3. “缺少英文”等字段问题只能作为某条未完成内容的原因出现，不能独立制造告警。
4. 每条待办尽可能进入具体对象，而不是仅进入模块列表。
5. 单个数据源失败时局部降级，不能让整个仪表盘变空。

## 生命周期状态

### 新手开始

当系统没有任何已发布页面和已发布新闻时进入新手状态。首页显示设置进度、建议下一步和五项基础任务：

1. 建立页面结构
2. 设置首页 Banner
3. 添加团队成员
4. 创建第一篇新闻
5. 发布第一个页面或新闻

每项任务的完成状态从真实数据自动推导。建议下一步始终是第一项未完成任务。

### 日常运营

当至少存在一个已发布页面或已发布新闻时进入日常状态。首页优先显示：

1. 已修改但未发布的页面
2. 尚未发布的新闻草稿
3. 会影响前台体验的遗漏配置，例如没有启用的 Banner 或没有团队成员
4. 未读留言

### 无待办

日常状态下没有任何待完成事项时，主要区域显示网站运行正常。保留最近发布和快速入口，不制造虚假的紧迫感。

## 数据模型

仪表盘继续并行读取现有接口，不新增聚合后端接口：

- `/api/admin/pages/tree`
- `/api/admin/news?pageSize=50`
- `/api/banners/all`
- `/api/team/all`
- `/api/contact/messages/unread-count`

新增纯函数模型 `adminDashboardModel.mjs`，输入上述接口的标准化数据，输出：

- `mode`: `onboarding` 或 `operations`
- `setupTasks`: 新手任务及完成状态
- `attentionItems`: 排序后的真实待办
- `recentItems`: 最近发布内容
- `isHealthy`: 日常状态是否无待办

数据源失败信息单独保留，界面在相应区域显示“部分数据暂时无法同步”和重试操作。

## 待办生成与排序

### 页面

只有 `has_draft` 的页面进入待办。标题为“页面有修改尚未发布”。如果同一页面 `missing_en`，将“英文标题尚未完成”放进说明文字。点击进入 `/admin/studio?id=<pageId>`。

### 新闻

只有 `status === draft` 的新闻进入待办。缺少英文时在说明中解释，否则显示最后更新时间。点击进入 `/admin/news?id=<newsId>`，新闻中心需要支持从查询参数直接打开编辑器。

### 配置

已运营网站没有启用 Banner 时显示设置事项，进入 `/admin/banners`。没有启用团队成员时显示设置事项，进入 `/admin/team`。

### 留言

未读留言数量大于零时显示一个汇总事项，进入 `/admin/messages`。

### 排序

1. 阻碍内容完成的问题
2. 页面未发布修改
3. 新闻草稿
4. 配置遗漏
5. 未读留言

同一优先级按最后更新时间从新到旧排列。首屏最多显示六条，避免形成第二个内容列表。

## 页面布局

### 顶部

- 标题与当前状态文案
- 全局搜索保留
- “查看前台”和“新增内容”主操作

### 新手状态

- 左侧：建议下一步的深色重点区
- 右侧：当前准备状态和完成数量
- 下方：五项设置清单

### 日常状态

- 左侧主区：待完成事项或运行正常状态
- 右侧窄区：快速开始入口
- 下方：最近发布内容
- 数据同步失败时显示局部提示

## 交互

- 待办整行可点击，并提供明确的文字操作。
- 页面草稿直接进入对应 Studio 页面。
- 新闻草稿通过查询参数直接打开对应编辑器。
- 快速入口进入新闻、活动、Banner 和媒体模块。
- 监听现有 `hkba:content-updated` 与 `hkba:messages-updated` 事件并自动刷新。
- 重试只重新加载仪表盘数据，不刷新整个后台页面。

## 加载、空状态与错误

- 加载时使用与最终版块形状一致的骨架，不显示居中转圈。
- 新手状态必须解释完成每一步的价值。
- 无待办状态显示“网站运行正常”和最近发布。
- 所有数据源都失败时显示完整错误状态和重试按钮。
- 部分失败时保留已加载内容，并列出无法同步的来源。

## 响应式

- 宽屏为主区和快速入口双栏。
- 低于 1100px 时改为单栏，待办在快速入口之前。
- 保持现有后台侧栏行为，不修改导航结构。

## 可访问性

- 待办行使用真实链接，支持键盘导航。
- 状态不能只依赖颜色，必须有文字标签。
- 焦点轮廓沿用后台青色焦点样式。
- 动效限制在 150-200ms 的背景、边框和位移反馈，并尊重减少动态效果设置。

## 测试

### 数据模型单元测试

- 无发布内容时进入新手状态
- 新手任务按真实数据完成
- 有发布内容时进入日常状态
- 只有页面草稿时才生成页面待办
- 缺少英文只作为草稿说明出现
- 新闻草稿生成可直达编辑器的链接
- 配置遗漏和未读留言生成正确事项
- 待办排序稳定且最多六条
- 无待办时返回健康状态

### 界面验证

- 新手、日常、健康、部分失败和全部失败状态均可渲染
- 查询参数能够打开指定新闻
- 内容更新事件触发仪表盘刷新
- 桌面宽屏和 1100px 附近没有横向溢出

## 非目标

- 不新增图表、访问量分析或历史趋势。
- 不重做左侧导航。
- 不新增后端数据表或设置完成标记。
- 不在本次实现中增加活动的新版草稿工作流。
