# HKBA 轻量页面构建后台总设计

日期：2026-07-15
状态：待用户审核
产品范围：HKBA 官网后台、页面构建器、新闻发布、媒体管理与发布系统

## 1. 背景与边界

HKBA 官网需要从基础 CRUD 后台升级为一个轻量、可扩展的页面构建后台。管理员应当能够在不修改代码的情况下管理前台栏目、页面、组件、中英文内容、新闻和媒体，并通过草稿、预览、发布和回退流程安全更新官网。

本设计面向 `btcsam/hkba` 当前 `main` 分支。项目采用 Next.js 16 + React 19 前端、Express 后端、`better-sqlite3` 数据库、JWT 管理员鉴权和本地上传目录，并通过 Next.js 同源代理向前台提供 `/api/*` 与 `/uploads/*`。本设计以现有可运行架构为起点，渐进升级后台，不在首期同时重写框架、数据库和部署链路。

### 1.1 当前代码映射

- `frontend/src/app/admin/pages/page.tsx`：现有页面管理只编辑固定 slug 的中英文标题和 HTML 正文。
- `frontend/src/app/admin/news/page.tsx`：现有新闻管理支持中英文标题、摘要、HTML 正文、封面、分类和发布开关。
- `frontend/src/components/admin/FormControls.tsx`：可复用现有双语字段、图片字段和基础表单控件。
- `backend/routes/pages.js`、`backend/routes/news.js`：现有页面和新闻 REST API 的渐进改造入口。
- `backend/routes/media.js`、`backend/routes/upload.js`：现有媒体库和本地上传入口。
- `backend/db/schema.sql`：当前 SQLite schema；已有 `pages`、`news`、`media`、成员、合作伙伴、里程碑和统计数据。
- `frontend/src/proxy.ts`：保持单域名前台、API 和上传资源代理边界。

现有能力继续运行，新页面构建器通过新增版本表、组件表和发布服务逐步接管页面及新闻内容。迁移期间不删除旧字段，直到旧数据完成转换、前台切换和回滚窗口结束。

## 2. 产品目标

- 登录后台后，以“星系神经图”展示整个管理系统，而不是直接进入页面列表。
- 管理员可以新增、复制、隐藏、删除和移动栏目与页面。
- 页面由经过设计的预设组件组成；管理员可以添加、删除、排序和配置组件，但不能任意修改 CSS。
- 中央页面画布始终保持宽阔，左右面板按需展开，并提供专注模式。
- 新闻正文和新闻展示都采用组件化设计。
- 新闻组件支持全部年份、最新年份、指定年份和访客选择年份。
- 所有图片字段支持拖动上传，也可以从统一媒体库选择已有素材。
- 中文和英文在同一后台管理，并提供翻译缺失提示。
- 所有修改先保存为草稿，经预览确认后发布；发布版本可回退。
- 后台保持轻量：优先满足协会官网长期内容运营，不建设无限自由的 Webflow 式设计器。

## 3. 非目标

首期不包含：

- 任意 CSS、JavaScript 或 HTML 编辑器。
- 管理员自由改变组件内部网格、字体体系和品牌颜色。
- 实时多人协同光标和类似在线文档的逐字符协作。
- 无限保存全部历史版本。
- 多级内容审批链和复杂媒体文件夹权限。
- 通用电商、会员付费、订单或客户关系管理功能。

这些能力只有在明确业务需求出现后才进入后续设计。

## 4. 后台信息架构

后台一级模块由星系神经图呈现：

```text
HKBA
├── 网站
│   ├── 栏目与页面
│   ├── 页面工作室
│   └── 导航与 SEO
├── 内容
│   ├── 新闻发布中心
│   ├── 新闻栏目与标签
│   └── 草稿与待发布
├── 媒体
│   ├── 图片
│   ├── 文件
│   └── 未使用素材
└── 系统
    ├── 用户与角色
    ├── 发布记录
    ├── 审计日志
    └── 网站设置
```

星系节点承担导航、状态和提醒功能。节点状态包括：正常、存在草稿、待发布、英文缺失、处理失败和需要管理员关注。节点数量变多时，系统必须提供搜索、缩放、自动聚焦和返回中心节点，不依赖用户在大图中手动寻找。

## 5. 栏目与页面

### 5.1 栏目

栏目是导航和层级容器，可以包含子栏目及页面。栏目支持：

- 新增、复制、改名、删除和排序。
- 拖动改变父栏目，但不允许形成循环层级。
- 中英文名称、稳定路径、导航显示状态和外部跳转。
- 栏目封面、SEO 标题、SEO 描述和社交分享图片。
- 最多三级栏目；更深层级应通过页面内容或标签组织。

删除包含子项的栏目时，管理员必须先选择“移动子项”或“连同子项移入回收站”。系统不执行静默级联永久删除。

### 5.2 页面

页面支持：

- 新建空白页面或从模板创建。
- 复制页面及其草稿组件。
- 隐藏、发布、取消发布和移入回收站。
- 调整导航位置、页面路径及上级栏目。
- 编辑中文和英文内容。
- 预览桌面、平板和手机效果。
- 查看历史版本并回退。

页面路径在首次发布后保持稳定。修改路径时系统提示 SEO 影响，并生成重定向记录。

## 6. 页面工作室

页面工作室采用“可收起双侧栏 + 专注模式”：

- 左侧常驻一条窄图标栏，按需打开页面树、组件结构或组件库抽屉。
- 中央是主要页面画布，按真实前台组件顺序渲染。
- 右侧常驻一条窄图标栏，按需打开组件属性、页面设置、版本历史抽屉。
- 展开的抽屉覆盖画布边缘，不永久压缩中央页面。
- 专注模式隐藏全部面板，保留接近全屏的页面预览。
- `Tab` 切换面板显示，`Esc` 退出专注或关闭当前抽屉。

管理员可以把预设组件拖入页面、拖动排序、复制、隐藏和删除。组件删除先进入当前草稿版本；正式网站只有在新版本发布后才改变。

## 7. 组件模型

组件由开发人员通过组件注册表定义。每个组件定义包括：

- 唯一类型标识和版本号。
- 中文名称、英文名称、分类和说明。
- 配置 schema、默认值和服务端验证规则。
- 允许出现的页面类型。
- 支持的语言字段和翻译完整度规则。
- 图片比例、响应式行为和空状态。
- 前台渲染器、后台预览器和必要的数据查询器。
- 配置迁移函数，用于组件升级后兼容旧页面。

管理员只能修改 schema 允许的内容和有限显示选项。管理员不能输入自定义 CSS 类、脚本或任意 HTML。

首批组件的详细定义见 [组件目录与配置规范](./2026-07-15-hkba-component-catalog.md)。

## 8. 新闻发布

新闻采用两层组件化：

1. 新闻正文由标题区、摘要、富文本、图片、图集、视频、引用、附件和相关链接等 `NewsBlock` 组成。
2. 前台页面通过新闻卡片、新闻列表、焦点新闻、年度归档、栏目标签和相关新闻等展示组件引用已发布新闻。

新闻只维护一份，不把文章复制到不同页面。页面组件通过年份、栏目、标签、数量和排序条件查询新闻。

新闻年份默认从 `publishedAt` 的年份计算。为满足年度报告或跨年活动，编辑人员可设置 `displayYear` 覆盖显示年份。筛选规则优先使用 `displayYear`，未设置时使用 `publishedAt` 年份。

新闻支持草稿、待发布、已发布、定时发布、已撤回和回收站状态。首期可先实现草稿、已发布和已撤回；定时发布属于后续增强。

## 9. 媒体管理

所有图片字段同时支持直接拖动上传和媒体库选择：

1. 客户端显示即时预览和上传进度。
2. 服务端验证 MIME、扩展名、文件头、大小和像素尺寸。
3. 保存原图并生成 WebP/AVIF 及常用响应式尺寸。
4. 建立 `MediaAsset`，保存替代文字、尺寸、上传者和引用关系。
5. 组件引用媒体 ID，不在内容中复制永久 URL。

替换媒体时，管理员可选择只更新当前组件或创建新的媒体资产。删除媒体前显示所有引用页面、新闻和版本；仍被正式版本引用的媒体不能永久删除。

## 10. 中英文

- 页面、栏目、新闻和需要翻译的组件字段使用明确的中文与英文字段。
- 后台提供语言切换和并排检查入口。
- 星系节点、页面树和发布检查显示英文缺失数量。
- 默认允许中文先保存草稿。
- 正式发布规则由页面设置决定：`必须双语完整` 或 `允许单语发布`。
- HKBA 官网默认使用“必须双语完整”；超级管理员可以对单次发布作出明确覆盖并留下审计记录。

## 11. 草稿、预览、发布与回退

- 编辑操作自动保存到草稿版本，并使用修订号检测多人覆盖。
- 发布前执行组件 schema、双语完整度、链接、媒体、路径和 SEO 检查。
- 预览使用短期令牌访问未发布版本，不改变正式站点。
- 发布在一个数据库事务中切换 `publishedVersionId`，失败时继续提供旧版本。
- 发布完成后只刷新受影响页面和查询缓存。
- 页面保留最近 20 个发布版本；草稿修订保留 30 天，并始终至少保留最近 20 次修订。
- 回退并不删除新版本，而是以历史版本生成一个新的草稿，确认后再次发布。

数据、接口和状态规则见 [数据、API 与发布规范](./2026-07-15-hkba-data-api-publishing.md)。

## 12. 权限与审计

首期角色：

- 超级管理员：用户、权限、系统设置和所有内容。
- 内容编辑：页面、新闻和媒体编辑；可以保存草稿和提交发布。
- 发布人员：检查、预览、发布、撤回和回退。

编辑人员不能提升自己的权限。登录使用服务端 HttpOnly、Secure、SameSite Cookie 会话，不把长期令牌存入 `localStorage`。登录、权限变更、删除、发布、回退和媒体永久删除写入审计日志。

## 13. 技术架构

轻量首选是保留当前前后端分离部署，新增领域服务而不改变单域名访问方式：

```text
Browser
├── Public Website
└── Admin Studio
        │
        ▼
Next.js 16 Frontend
├── Public Renderer
├── Galaxy Dashboard
└── Page Studio
        │
        ▼ same-origin proxy
Express API
├── Auth & Permissions
├── Page / Component Service
├── News Service
├── Media Service
└── Publish Service
        │
        ├── SQLite + versioned migrations
        ├── Local uploads + media metadata
        └── Existing Baota / Next proxy deployment
```

第一阶段继续使用 SQLite 和本地上传，优先完成页面树、组件模型、新闻组件、草稿和发布流程。第二阶段在现有接口边界稳定后，再评估迁移到 PostgreSQL 和兼容 S3 的对象存储或阿里云 OSS。迁移不能与页面构建器首期上线绑定为同一次高风险切换。

## 14. 错误处理

- 表单执行客户端即时提示和服务端最终验证。
- 上传失败不替换原媒体，允许单文件重试。
- 修订号不一致时阻止静默覆盖，提供刷新、复制为新草稿或重新应用修改。
- 发布检查列出具体页面、组件和字段，不只返回“发布失败”。
- 发布事务失败时正式版本保持不变。
- API 采用稳定错误代码，界面文案可以本地化。
- 回收站提供 30 天恢复期；永久删除需要二次确认和相应权限。

## 15. 可访问性、响应式与 SEO

- 后台主要面向桌面，最低支持 1280px 宽度；较窄窗口自动进入单抽屉模式。
- 画布可切换桌面、平板和手机宽度。
- 拖动操作必须提供键盘移动替代方式。
- 颜色状态同时提供图标和文字，不只依赖颜色。
- 图片组件要求替代文字；装饰图片可明确标记为空替代文本。
- 页面和新闻支持 canonical、Open Graph、结构化数据和站点地图。
- 新闻发布后更新新闻站点地图和相关页面缓存。

UI 细则见 [UI 与交互规范](./2026-07-15-hkba-ui-interaction-system.md)。

## 16. 分阶段交付

### 第一阶段：核心可用

- 登录和角色基础。
- 星系控制中心。
- 栏目与页面树。
- 可收起页面工作室。
- 首批页面和新闻组件。
- 中英文内容。
- 媒体拖动上传和媒体库。
- 草稿、预览和发布。

### 第二阶段：安全完善

- 版本差异与回退。
- 完整角色权限和审计日志。
- 媒体引用保护。
- 自动备份与恢复演练。
- 路径重定向和更完整 SEO 检查。

### 第三阶段：体验增强

- 定时发布。
- 组件模板和跨页面内容复用。
- 更细致的操作分析。
- 经实际需求验证后的协同编辑。

验收、迁移和运维边界见 [验收、迁移与运维规范](./2026-07-15-hkba-acceptance-migration-operations.md)。

## 17. 成功标准

- 非技术管理员可以独立新增栏目和页面，组合组件并发布中英文内容。
- 新闻发布一次后可被不同页面的新闻组件按年份和栏目引用。
- 页面编辑时中央画布不会被常驻侧栏挤压。
- 图片上传、复用、引用检查和替代文字形成完整流程。
- 未通过发布检查或发布事务失败时，正式官网不受影响。
- 管理员可以定位最近发布版本并安全回退。
- 实施计划能够把每个设计模块对应到当前 Next.js、Express、SQLite 文件、增量迁移和真实验证命令。
